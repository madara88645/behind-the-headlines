# AGENTS.md - guide for AI coding assistants

You are helping a first-year student team add games to **Behind the Headlines**: browser games that make a real survey about data centres playable, for the Bournemouth University Induction Hack 2026 ("Data centres: behind the headlines - make data playable").

Read this whole file before writing code. When a rule here conflicts with a general habit of yours, this file wins. If a request would break a rule, say so and suggest the closest option that doesn't.

---

## 1. What the judges look for
The official brief asks for a **working software artefact** that makes **meaningful use of the supplied survey**, is **genuinely interactive** ("a dashboard isn't automatically interactive just because it has filters") and gives the player **something meaningful to do**. Judging: **IDEA, DATA, INTERACTION, INSIGHT, BUILD, TEAMWORK**. The rules also say: *"Don't misrepresent the data."*

The thread through every game: **DATA ≠ OPINION ≠ ASSUMPTION**.
- **DATA** - measured, with a source you can check (e.g. CSO electricity figures).
- **OPINION** - what survey respondents said they think or feel. Real, and itself data about people - but not proof about data centres.
- **ASSUMPTION** - what the player guesses or takes for granted before seeing evidence.

A good new game: a player does something (predicts, sorts, bets, builds, negotiates) → the game reveals the survey and the evidence → the player discovers a gap between the three. 3-6 minutes, clear start and end screen, "Play again".

---

## 2. Hard rules (never break these)
1. **Plain HTML + CSS + JavaScript.** No frameworks, no npm, no bundler, no TypeScript, no build step. (The `video/` folder is the only exception and is separate.)
2. **Must work by double-clicking a file (file://) in Safari AND Chrome.**
   - Game pages live in the **project root** (`<slug>.html`). Their CSS/JS live in `games/<slug>/`.
   - **Never reference `../` from a page.** Safari only lets a file:// page load files from its own folder and below. A page inside `games/` cannot load `data/` - this already broke all three games once.
   - Load scripts with classic `<script src>` tags. **No `fetch()` of local files, no `type="module"`, no `import`.**
3. **Survey numbers only come from `window.Survey`** (see `shared/survey.js`) at runtime. Never type a survey percentage into HTML, JS or copy.
4. **Facts, verdicts, policies and news claims only come from `window.DC_FACTS`** (`data/facts.js`), and every fact shown has a visible source link.
5. **Never edit `data/survey_stats.js` or `data/survey_stats.json` by hand.** They are generated by `tools/extract_survey.py`.
6. **Never commit or read the raw survey spreadsheet (`.xlsx`).** Only aggregated data is shared. There are no individual responses anywhere in this repo - don't invent any.
7. **Don't modify another game** (`bubble-sort`, `5km`, `rigged`, or a teammate's) or the shared files (`shared/`, `data/`, `tools/`) unless the task is explicitly about them.
8. **External resources:** Google Fonts only (with a system fallback). No other CDNs, no remote images, no analytics, no backend. Draw with inline SVG and CSS.
9. **All player-facing text is in English.**

## 4. The data

### 4.1 The survey
*Social Acceptance of Sustainable Data Centres in Ireland* - Maynooth University, **200 respondents, 104 questions** (ids `q1`-`q104`). Always describe it as **"200 people in Ireland (Maynooth University survey)"**. Never write "Ireland thinks" or "Irish people believe" - write "in this survey".

**Before designing, read `data/survey_digest.txt`.** It lists every question with its options and percentages.

Question blocks and who already uses them - prefer the unused ones for new games:

|---|---|---|

Data rules:
- **Groups under 30 people** (cross-tabs) must show a visible "small group (n = X)" caveat. Don't build a headline claim on them.
- **Suppressed cells** (fewer than 3 people) come back as `null`. Show "too few people to show" - never 0.
- **Multi-select questions** (q16, q52, q53, q88) add up to more than 100%. Never draw them as a pie or as parts of a whole.
- A cross-tab shows a **pattern, not a cause**. Say so when you show one.
- Percentages are of the people who **answered that question** (`n_answered`, between 170 and 200), not always 200.

### 4.2 `window.Survey` (shared/survey.js)
```js
Survey.n                         // 200
Survey.q('q77')                  // question object; throws on an unknown id
//   { id, text, group, item, kind, themes, n_answered, ordered, options: [{ label, short, value, count, pct }] }
//   kind: 'single' | 'truefalse' | 'multi' | 'scale_numeric'
//   ordered questions list options low -> high with a 1-based `value`
//   (5-point agree scales: 1 Strongly Disagree ... 5 Strongly Agree; `short` drops the "(n)" suffix)
//   true/false items q18-q25 have options 'True', 'False', "Don't know"
Survey.label('q26')              // short text: the matrix item, else the question
Survey.find(/within 5 km/)       // first question whose text matches
Survey.pct('q96', /supportive/)  // % choosing matching options (label, [labels], RegExp or fn)
Survey.pct('q77', o => o.value >= 4)      // e.g. "somewhat" + "completely acceptable"
Survey.count('q18', 'True')      // headcount
Survey.agree('q26'), Survey.disagree('q26'), Survey.neutral('q26')   // 5-point agree scales
Survey.mean('q17')               // mean of an ordered question (or null)
Survey.within('q17', 'A great deal', 'q18', 'True')   // -> { pct, n } or null if suppressed / not available
Survey.crosstab('q4', 'q77')     // rows [{ label, short, value, n, cells: [{ label, short, value, count, pct }] }]
Survey.fmt(55.5)                 // "56%"
```
Cross-tabs only exist when the **"by" question** is one of: q1, q2, q3, q4, q6, q7, q9, q11, q14, q15, q16, q17, q33, q38, q63, q66, q77, q96, q97, q98 (against any other categorical question). `within()`/`crosstab()` return `null` otherwise. Need a new "by" question? Add its wording to `CROSSTAB_BY` in `tools/extract_survey.py` and ask the team member who has the original `.xlsx` to re-run the script - don't fake it.

### 4.3 `window.DC_FACTS` (data/facts.js)
- `csoSeries` - data-centre share of Ireland's metered electricity 2015-2025 (5% → 23%) and GWh, plus a 2025 comparison with households.
- `trueFalse.q18` … `q25` - verdict, tag, short and long explanation, sources for each true/false survey item.
- `facts[]` - `{ id, topic, text, source, year, url, confidence }`.
- `policies[]` - how other places handled data centres (Amsterdam, Netherlands, Singapore, Germany, Denmark, Virginia, EU, Ireland).
- `claims[]` - **paraphrased** news claims with outlet, date, verdict, evidence, what's missing, url.

Adding a fact: add it to `data/facts.js` with a real URL you (or the person prompting you) actually opened, a `year`, and an honest `confidence` (`high` = official statistics/regulator/IEA, `medium` = reputable reporting, `low` = single or contested estimate - show a caveat in the game). Paraphrase news - never copy headlines or articles word for word. Never invent a number or a source. If you can't verify something, leave it out and say so.

## 5. Adding a new game - step by step
1. **Spec first.** Write `docs/specs/<slug>.md`: tagline, what the player does minute by minute, which question ids and facts each step uses, the insight moment, the end screen, and the design direction (see section 6). Show it to the person prompting you before coding.
2. **Files:** `<slug>.html` in the root; `games/<slug>/style.css`, `games/<slug>/game.js` (more helper JS files are fine).
3. **Page skeleton** (keep this script order):
   ```html
   <!DOCTYPE html>
   <html lang="en">
   <head>
     <meta charset="utf-8">
     <meta name="viewport" content="width=device-width, initial-scale=1">
     <title>Game Name · Behind the Headlines</title>
     <!-- optional: Google Fonts <link> here -->
     <link rel="stylesheet" href="games/<slug>/style.css">
   </head>
   <body>
     <a href="index.html">← All games</a>
     <!-- screens -->
     <script src="data/survey_stats.js"></script>
     <script src="data/facts.js"></script>
     <script src="shared/survey.js"></script>
     <script src="games/<slug>/game.js"></script>
   </body>
   </html>
   ```
4. **Screens:** start screen (what you'll do + "Built on a survey of 200 people in Ireland (Maynooth University)"), the play loop, reveal/debrief screens, an end screen that compares the player with the survey and **lists every source used**, and a working **Play again** that fully resets state.
5. **Label everything** the player sees as DATA / OPINION / ASSUMPTION, consistently. Any model or score built on the survey (a "meter", a simulated vote) gets a short **"How this is calculated"** panel saying which questions feed it and that it's a simplification.
6. **Debug screens:** support `#screen=<name>` in the URL to jump to each major screen with sample answers (normal play unaffected). List the names in a comment at the top of `game.js`.
7. **Remember player answers only in `localStorage`**, wrapped in try/catch, labelled honestly ("players on this device" - never "live poll").
8. **Launcher:** add a card to `index.html` in the `.grid` (give it its own art in the game's style) and a row to the table in `README.md`.

## 6. Design
Each game has its **own visual identity**. Don't copy another game's look, and avoid the generic "AI-generated" looks: cream background + serif + terracotta; near-black + one neon accent; newspaper columns with hairlines.

Already taken - pick something clearly different:
| Game | Concept | Palette | Fonts |
|---|---|---|---|
| Bubble Sort | science-museum soap bubbles | periwinkle #EEF0FF, cobalt #1F5BFF, raspberry #D6246E, marigold #F2A007 | Bricolage Grotesque, Atkinson Hyperlegible, JetBrains Mono |
| 5 KM | Irish planning notice + map | field green #DDE8CF, notice yellow #FFD400, orange #E4572E | Archivo, Public Sans, IBM Plex Mono |
| Rigged | psychology-lab paperwork, red pen | lab mint #E6F0EA, navy #14213D, red #D62828 | Chivo, Chivo Mono, Caveat |
| Launcher | "Data ≠ Opinion ≠ Assumption" | grey #F3F4F6, ink #111318, orange ≠ #E4572E | Schibsted Grotesk, IBM Plex Mono |

How to design a new one: ground it in something real from the subject's world (a server hall, a council meeting, a phone feed, an electricity bill, a weather map...). Define colours as CSS custom properties on `:root`. Pick one **signature moment** the game will be remembered for (the bubble gulp, the 56% → 30% meter drop, the RIGGED stamp) and keep everything else calm.

Quality floor:
- Built and tested for a **laptop screen, 1280×800 and larger**. It must still be usable on a narrow window (no horizontal scroll), but phones are not a priority.
- Keyboard playable: real `<button>`/`<input>` elements and visible focus.
- Respect `prefers-reduced-motion`. Text contrast at least WCAG AA. Never rely on colour alone for right/wrong - add an icon or a word.
- No console errors. If a question id is missing, skip that step instead of crashing.
- Copy: plain, friendly, sentence case, no lorem ipsum, no TODOs left on screen.

## 7. Check your work before a pull request
1. `node --check games/<slug>/*.js` passes.
2. `tools/qa_shot.sh <slug>.html /tmp/shot.png 1280 800 "#screen=<name>"` for every debug screen: look at the PNG and make sure no console errors are printed. It needs Google Chrome on macOS.
3. `grep -n '\.\./' <slug>.html` prints nothing.
4. **Double-click `<slug>.html` in Finder and play it to the end in Safari, then in Chrome.** Check that the first button works, that every number you show matches `data/survey_digest.txt`, and that Play again resets everything.
5. Open `index.html` and check that your card links to the game and back.
